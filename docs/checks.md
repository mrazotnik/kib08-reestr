# Протокол проверки КТ4

Основные проверки начаты 22 ноября 2026 года. Повторный прогон для «Реестра обращений» выполнен 23 ноября. Целевая метрика из I14 реестра — полный маршрут хотя бы для 9 из 10 подготовленных синтетических случаев.

## Результат автоматической проверки

Во временном профиле Chrome браузерный тест начинает с пустого журнала. Для каждого случая вводит данные через форму, прикрепляет PNG, открывает карточку, сохраняет ручное решение и скачивает TXT. Проверяются дата, площадка, адрес ресурса, тип, исходное наблюдение, текст решения и имя приложения. Изображение должно загрузиться в карточке. Демо-данные сами по себе успехом не считаются.

Итог браузерного прогона: 10 / 10 = 100%. Порог из реестра: 9 / 10 = 90%. Это функциональная проверка, выполненная автоматизацией. Оценка удобства работы сотрудника требует отдельного прогона с человеком.

В новой версии повторно пройдены все 10 случаев. Кроме основной последовательности, проверили быстрый прием по тексту, снимку и ссылке, вставку изображения из буфера и переход после дозаполнения полей. Поврежденное изображение отклонено. Журнал, сохраненный в предыдущей версии, прочитан. Пустой чек-лист и официальный адрес блокируют подготовку черновика. Повторный и внешний адреса отклоняются. Пояснение сохраняется при переходе между вкладками карточки, экспорт остается закрытым до сохранения решения.

В браузерном прогоне также проверены поиск, фильтры из сводки и строки статусов, сортировка, увеличение снимка, закрытие правой панели и возврат фокуса к строке. На ширине 320 px журнал, фильтр и карточка помещались без горизонтальной прокрутки. На ширине 390 px проверены открытие и закрытие обеих форм. Ошибок JavaScript и HTTP-запросов к внешним сайтам не зафиксировано.

## Как повторить

Тест модели запускается средствами Node.js:

```sh
node --test tests/model.test.cjs
```

Для браузерного прогона требуется Playwright с Chromium. Если используете установленный Chrome, укажите путь через CHROME_BIN. Если Playwright находится отдельно от проекта, задайте PLAYWRIGHT_MODULE. Для теста по HTTP укажите TEST_BASE_URL. Без него откроется локальный index.html.

```sh
node tests/browser.cjs
```

## Замер времени для финального отчета

Используйте два похожих учебных кейса с одинаковым количеством обязательных полей. В ручном варианте участник получает исходное сообщение, перечень официальных адресов, снимок и шаблон TXT. В варианте со стендом он получает такой же набор данных. Начало замера — получение задания, конец — готовый черновик с нужными полями. Для следующего участника поменяйте порядок сценариев. Фиксируйте ошибки наравне со временем.

| Участник | Кейс и порядок | Вручную, с | В стенде, с | Разница, с | Пропущенные поля |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

Разница равна времени вручную минус время в стенде. Процент экономии равен разнице, деленной на время вручную и умноженной на 100%. Перед сравнением убедитесь, что оба черновика одинаково полны. Замер времени людей к этому протоколу пока не приложен.
