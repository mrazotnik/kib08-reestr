# Реестр обращений

Команда KIB-08 · КТ4 · MVP

[Открыть демо на GitHub Pages](https://mrazotnik.github.io/kib08-reestr/)

## Что решает проект

Маркетолог небольшого магазина получает сообщения о страницах, профилях и объявлениях, которые выглядят как официальные. Если ссылка осталась в одной переписке, а снимок экрана в другой, перед обращением на площадку приходится собирать материалы заново.

Реестр обращений хранит сообщение, снимок и результат проверки в одной карточке. Маркетолог сверяет адрес со справочником официальных каналов и сам решает, есть ли основания для обращения. Если есть, он скачивает черновик в TXT и отдельно снимок для приложения.

## Как запустить

Распакуйте архив проекта и откройте `index.html` в Chrome. Для запуска нужны файлы из той же папки, включая `assets`. Установка и регистрация не требуются. Учебные случаи уже есть в журнале.

## Как повторить демонстрацию

1. В блоке **Быстрый прием** введите учебное сообщение, например `Покупатель прислал снимок профиля с названием магазина`, и нажмите **Сохранить случай**. Откроется карточка во **Входящих**. Ее можно дополнить позже и передать на проверку.
2. Для демонстрации проверки откройте готовый случай **Профиль с именем магазина**. На вкладке **Проверка** сравните адрес из сообщения с официальным адресом и откройте снимок.
3. Отметьте пункты чек-листа, выберите **Подготовить черновик** и напишите пояснение. Например, `На снимке видно название магазина, а адрес профиля отличается от официального`.
4. Нажмите **Сохранить решение**, затем **Скачать черновик**. Откройте TXT и проверьте, что в нем есть адрес, дата, наблюдение, результат проверки и имя файла со снимком.
5. Для контрольного случая создайте запись через **Заполнить всё сразу**. Выберите площадку **Лента** и укажите официальный учебный адрес `https://lenta.example/company-a`. При совпадении адресов подготовка черновика недоступна. Случай можно закрыть без черновика.

## Что взяли из исследования

- **Product Hunt.** В карточке Checker сразу понятно, для кого продукт и какую задачу он решает. На нашем показе формулируем результат так же конкретно. Маркетолог получает черновик обращения после сверки адреса и снимка. [Карточка Checker](https://www.producthunt.com/products/checker-real-time-signup-validator)
- **Show HN.** Площадка предлагает дать зрителю попробовать рабочий продукт без лишних шагов. В нашем демо первый учебный случай уже есть в журнале и открывается без регистрации. [Правила Show HN](https://news.ycombinator.com/showhn.html)
- **Peerlist Launchpad.** Карточка SpoofGuard.io показывает работу через последовательность действий. На нашем показе участник проходит один учебный случай до скачивания черновика и отмечает, где ему понадобилась подсказка. [Карточка SpoofGuard.io](https://peerlist.io/nickbecker/project/spoofguardio)

Сравнение сервисов защиты бренда, подачи жалобы на площадку и ручного учета приведено в [обзоре аналогов](docs/research.md).

## Что проверили

Цель команды по листу Реестр тем, I14, - довести до выгрузки полного черновика не менее 9 из 10 учебных случаев. В автоматическом браузерном прогоне черновик с нужными полями скачался для всех 10 из 10 случаев. Сравнительный замер времени вручную и в прототипе предстоит провести с участниками. [Протокол проверки](docs/checks.md)

В демо используются вымышленные профили и снимки. Записи хранятся в текущем браузере. Обращения на площадки подает сам сотрудник за пределами прототипа. [Модель угроз](docs/threat-model.md)
